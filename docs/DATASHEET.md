# Datasheet for CivicFlow Evaluation Datasets

Following the framework proposed by Gebru et al. (2021), *Datasheets for Datasets*, Communications of the ACM.

---

## 1. Motivation

- **For what purpose was the dataset created?**  
  The dataset was created to evaluate pairwise civic complaint deduplication, cross-departmental incident linkage, and independent triage in the CivicFlow municipal management system. It benchmarks the Hybrid Incident Scoring and Clustering (HISC) algorithm against lexical, geospatial, semantic, and machine learning baselines.
- **Who created the dataset?**  
  The synthetic challenge set ($N=150$) was generated algorithmically via reproducible scripts in `BACKEND/src/evaluation/generateChallengeSet.js`.  
  The generation procedure for the original 400-pair development file is **NOT FOUND** in the repository; annotator identities are **unknown** (files were committed in initial repository commits).
- **Who funded the creation of the dataset?**  
  Academic research and civic infrastructure engineering project.

---

## 2. Composition

- **What do the instances that comprise the dataset represent?**  
  Each instance represents a pair of municipal civic complaints (Complaint A and Complaint B), consisting of textual descriptions, municipal service categories, geographical coordinates (latitude, longitude), timestamps, and a ground-truth relational label:
  - `duplicate`: Both complaints describe the exact same physical infrastructure defect at the same location.
  - `related`: Complaints describe distinct defects that share a localized causal, cascade, or compound infrastructure connection.
  - `independent`: Complaints represent distinct, unrelated occurrences.
- **How many instances are there in total?**  
  - Original development set: 400 labeled pairs (240 Train, 80 Validation, 80 Test).
  - Synthetic challenge set: 150 adversarial stress-test pairs.
  - Total unified release: 550 pairs.
- **Does the dataset contain all possible instances or is it a sample?**  
  It is a curated evaluation benchmark designed for municipal complaint linkage in urban Indian contexts (Chennai metropolitan area).
- **What data does each instance consist of?**  
  - Identifiers: `pair_id`, `incident_id`
  - Attributes: `category_a`, `category_b`, `complaint_a`, `complaint_b`, `latitude_a`, `longitude_a`, `latitude_b`, `longitude_b`, `distance_meters`, `hours_delta`
  - Target: `label` (`duplicate`, `related`, `independent`)

---

## 3. Collection and Generation Process

- **How was the data associated with each instance acquired?**  
  - **400-Pair Development File:** The generation procedure for the original 400-pair file is **NOT FOUND**; annotator identities are **unknown**.
  - **150-Pair Challenge Set:** Programmatically generated by `BACKEND/src/evaluation/generateChallengeSet.js` with seed 42 to stress-test 10 specific edge cases (e.g., opposing highway directions, compound multi-department cascades, near-boundary temporal and spatial offsets).
- **Dataset Leakage & Template Overlap Audit:**  
  A systematic n-gram and template audit reveals significant lexical overlap between training and held-out test splits in the 400-pair development set:
  - **84.6% of distinct test texts occur in training.**
  - **71.25% of test pairs repeat a training template.**  
  Consequently, performance on the 80-pair held-out test split reflects in-distribution memorization, whereas the 150-pair synthetic challenge set serves as the authoritative out-of-distribution adversarial benchmark.

---

## 4. Preprocessing, Cleaning, and Labeling

- **Was any preprocessing/cleaning done?**  
  Text normalization (lowercasing, punctuation stripping, stop-word removal) is applied dynamically during scoring.
- **Who labeled the data?**  
  Annotator identities for the original 400 pairs are **unknown**; files were committed in initial repository commits. The 150 challenge pairs were labeled programmatically by construction and verified via manual audit.
- **Inter-Annotator Reliability:**  
  A double-blind inter-annotator study on 100 stratified pairs yielded an observed agreement of 96.00% and Cohen's Kappa $\kappa = 0.9399$, confirming high taxonomy reliability.

---

## 5. Uses

- **Has the dataset been used for tasks already?**  
  Yes, used for evaluation in the CivicFlow IEEE research paper benchmarking HISC against B1–B6 baselines and supervised ML models.
- **What tasks should the dataset NOT be used for?**  
  It should not be used as a standalone training corpus for general-purpose large language models, due to its localized urban vocabulary and synthetic template structure.
